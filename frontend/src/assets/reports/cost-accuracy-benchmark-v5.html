Scoring Rules, Methodology & Audit Scope

To ensure total transparency, the scores are computed via strict mathematical criteria:

  • Score A (Pricing Accuracy): Evaluates whether the active simulator values exactly equal the official AWS Price List rates (tolerance of 1e-9). Calculated as MATCH / (MATCH + DRIFT).
  • Score B₁ & B₂ (Coverage): Evaluates the proportion of modeled cost parameters against a real-world AWS audit. B₁ is a simple ratio, whereas B₂ weights omissions based on architectural severity.
  • Score C (Cost-Realism Score): Computes the final product (A × B₂). A score >90% represents the gold standard for cloud-billing simulation accuracy.

Audit Scope Boundaries:

  • In-Scope (Audited & Scored): All 7,511 active regional pricing parameters. This includes compute instance types (EC2/ECS/EKS/Lambda), database node classes (RDS/Aurora/DocumentDB/Neptune/ElastiCache/OpenSearch), storage volumes (EBS/S3/EFS/DynamoDB), and dynamic data transfer/request processing rates (ALB/NLB/CloudFront/API Gateway/Route 53/SNS/SQS/SES/Amplify) checked against the live AWS Price List API.
  • Out-of-Scope (Excluded from Score A): Static default fallbacks (unqueried baseline constants), regional service gaps where AWS offers no SKU (flagged as NO_API_DATA), free services with no billing variables (e.g. IAM, Security Groups), and simulation-only knobs (latency, rps).

Methodology Details:

  • MATCH: Exact equality vs the Price List API after replicating pipeline unit scaling + rounding (tolerance 1e-9); strict SKU predicates — no product ⇒ NO_API_DATA, never a wrong product.
  • Modeled Cost Factors: costParams + cost-driving primaryParams (instance selectors, counts, capacity units). Simulation-only knobs excluded.
  • Coverage per Service: Modeled / (Modeled + Known-Omitted), the "8 of 10 → 80%" rule.
  • Severity Weights: Critical 8 · High 5 · Medium-High 4 · Medium 3 · Low-Medium 2 · Low 1; modeled factors count flat 3.
